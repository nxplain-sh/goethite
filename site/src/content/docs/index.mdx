<Aside type="caution" title="Pre-alpha">
	goethite 0.3 filters, caches and forwards DNS over DNS over TLS or DNS over HTTPS, hardened for
	Linux, with per-client groups, a query log, a REST API, a terminal UI and the start of a web UI.
	Two nodes can share one configuration and one floating IP, and upgrades drop no query: try it,
	but do not rely on it yet. The full web UI, encrypted DNS for clients and recursion are still
	ahead; the cards below are the goals. See the [changelog](changelog/).
</Aside>

## What goethite aims to be

<CardGrid>
	<Card title="Security first" icon="padlock">
		Memory-safe Rust with no `unsafe` in the parsing and resolving core, no panics on network
		input, fuzzed parsers, and a written threat model.
	</Card>
	<Card title="Fast and bounded" icon="rocket">
		Sub-millisecond cached answers and million-rule filter lists in a small, bounded memory
		footprint, with every claim backed by a reproducible benchmark.
	</Card>
	<Card title="Highly available" icon="random">
		Every node resolves on its own. Clustering adds replicated config, a floating IP and
		zero-downtime reloads and upgrades.
	</Card>
	<Card title="Everyday filtering" icon="list-format">
		Hosts files, domain lists and AdGuard-style rules, per-client groups and schedules, CNAME
		uncloaking and safe search.
	</Card>
</CardGrid>

The [roadmap](https://github.com/nxplain-sh/goethite/blob/main/AGENTS.md#roadmap-respect-the-order)
lists what lands in which phase.
